# Authoritative membership related-source disposition

This inventory is scoped to the exact owner-accepted August 23, 2026 Pasco
appraiser parcel-membership snapshot. Parcel authority removes only the parcel
membership dependency. It does not convert an enrichment source into complete
coverage, authorize a remote acquisition, or create a parcel-to-contractor
relationship.

No BBB, contractor, permit, or Accela record dataset exists in the local
ignored evidence/data inventory. The only paths containing permit or BBB terms
are frozen contract fixtures, tests, documentation, and derived publication
artifacts that explicitly encode unavailable/null coverage. They are not
source data.

A sanitized, read-only assessment-development database check on 2026-08-30,
before migrations 022/023, found zero rows in each of `oracle_permits`,
`oracle_contractors`, and `oracle_permit_contractors`. After migrations
022-024 and the authoritative Loader transaction, those canonical tables still
contain no permit, contractor, or relationship rows, and the new contractor
authorization, dataset, source-record, and identity-match tables each contain
zero rows. These local counts corroborate that no related-source row was
loaded; they are not source coverage evidence and say nothing about how many
real permits or contractors exist.

## Disabled contractor staging boundary

Migrations 023/024 define immutable, separately scoped contractor source
authorization, dataset, source-record-version, and identity-match tables, plus
permit-relationship evidence columns and guards on the disabled legacy
relationship table. The application staging model requires a contained and
hash-bound local source, a strict versioned schema, partial coverage, a
separately hash-bound terms-evidence file, credential-free HTTPS source
identities, bounded source and line sizes, and deterministic identities.
Observation and retrieval timestamps are either recorded values or an explicit
unavailable state; they are never invented. The parser verifies both files
beneath `DATA_DIR`, rejects unknown, malformed, provider-incoherent and
duplicate records, and never performs remote acquisition.

Matching order is exact license number plus the same issuer and jurisdiction,
exact provider identity, then exact normalized legal name plus address and
phone. A name-only match is always ambiguous and remains unlinked. BBB
presence, rating, or accreditation is not a government license, permit
authorization, endorsement, qualification, or proof of workmanship. No
BBB-only record can create a property relationship. The contractor source,
dataset, record, and match staging tables have no parcel foreign key. The
separate relationship table declares a property foreign key but rejects all
inserts. Normalized linked contractor identity matches and all
permit-to-contractor relationship persistence are disabled in both application
and SQL paths until immutable target contractor, permit, and
relationship-source versions exist. Synthetic ambiguous and non-linking match
evidence can be evaluated without creating an operational relationship.

The external BBB dependency is an authorized API, licensed export, or
owner-supplied file accompanied by a reproducible source identity, a separate
immutable source authorization, documented
terms/retention permission, category/geographic scope, freshness, request/cost
limits, and a hash-bound terms-evidence file. No real source has passed this
boundary, no contractor staging row has been accepted, and operational
ingestion readiness is not claimed. Until the missing source and authorization
are supplied and independently verified, the production adapter fails closed
without making a request.
